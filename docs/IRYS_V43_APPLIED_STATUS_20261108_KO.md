### 1. 실제 알림의 후속 결과 저장
기존 V39 작업에 동일 저장소 main의 V30 수집 성공 완료 이벤트를 연결했다. 기존 14분/44분 cron은 보조 경로로 유지했다. 기존 기록·중복 방지·비강제 push·원격 재조회는 유지했다.

### 2. 관심 후보와 미완료 실제 알림의 공개 실시간 수집
Bitget·Bithumb 공식 WebSocket에서 체결과 호가 잔량을 수집한다. 기존 전체시장 탐색과 실제 알림 전송은 건드리지 않았다. 현재 후보 전체, 아직 60분 후속 추적이 필요한 실제 ACK, 각 거래소 BTC를 구독한다.

큰 정수 ID 보존, Bitget 초기 snapshot과 실시간 update 분리, Bithumb 호가 microsecond/체결 millisecond 구분, 중복·역순·미래시각·재접속공백 검사를 구현했다. 실제 수신에서 같은 millisecond지만 더 최신 순번인 호가 2건이 충돌로 잘못 처리되는 문제를 재현했고 순번을 보존해 수정했다. 초기 원본 54,868개 메시지 재생에서 오류0을 재확인했다.

### 3. 방향과 즉시 진입위험의 분리
매수·매도 체결금액, 실제 가격 반응, 보이는 호가 잔량 불균형과 보충, 스프레드, 연결 공백을 각각 기록한다. 매수체결 우세인데 가격이 하락하는 경우와 매도체결 우세인데 가격이 상승하는 경우를 구분한다. 흡수 가능성을 흡수 확정으로 표시하지 않으며 미래 확률을 임의로 만들지 않는다.

### 4. 실제 미래 호가와 초기 역행을 따로 기록
실제 ACK가 발생한 원래 bid/ask 기준을 보존하고, 목표시각 이후 실제 받은 호가만 5/15/30/60분 결과에 사용한다. LONG은 진입 ask/후속 bid, SHORT는 진입 bid/후속 ask를 구분한다. 과거 가격이나 한참 늦은 가격으로 정답을 꾸미지 않는다. 측정 지연, 미측정, 최초 관측된 근거이탈, 관측된 최대 유리·불리 움직임을 별도 기록한다.
