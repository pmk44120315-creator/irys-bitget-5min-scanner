## 2. 실제 구현된 기능
### 원래 보낸 방향 신호를 계속 반증
최근15분 안의 원본READY 종목은 신규후보 목록에서 빠져도 다시 관측한다. Worker는 그중 자신의 실제 Telegram ACK가 있고 원래 메시지ID·본문·방향·근거가격이 보존된 기록만 대상으로 한다.

첫 발송 이후 두 번의 새 호가와 마지막 호가가 모두 원래 근거가격을 반대로 넘었을 때만 INVALIDATED로 판정한다. LONG/BUY는 전체호가가 기준 아래로, SHORT는 전체호가가 기준 위로 이동해야 한다. 한 번의 흔들림·스프레드 접촉·재사용한 시각·다른종목·오래된 자료는 확정 무효로 만들지 않는다. 자료가 없으면 UNVERIFIED다. 최대15분 후에는 관찰기간 종료로 표시한다.

새 경고메시지를 반복 전송하는 대신 봇이 원래 보낸 메시지에 무효/기간종료 상태를 붙인다. 원래 발송가격·방향·사후성과는 덮어쓰지 않는다. 반대매매나 자동청산을 실행하지 않는다. 원래 메시지의 수정이 새 푸시 알림을 보장하지는 않는다. 기존 옛 메시지에 필요한 식별·근거가 없으면 추측해서 수정하지 않는다.

실패한 편집은 성공으로 기록하지 않고 보류상태를 유지한다. 외부에서 만든 임의 객체는 편집권한을 얻지 못하며, 내부 일회성 허가와 실제 메시지ID/채팅ID 응답을 대조한다. 토큰·비공개본문을 로그나 공개시장파일로 내보내지 않는다.

### 현재 신호와 과거 평가의 처리순서 분리
현재 체결·호가 신호파일을 먼저 게시한 후에 과거분봉을 수집해 별도캐시에 저장한다. 새캐시가 아직 없을 때 기존 분봉22개 묶음이 빈값으로 덮일 수 있는 경우를 재현하고 수정했다. 각 호가의 원래시각·미래자료 금지·가격무효화 검사를 유지한다. GitHub대기나5분Cron 자체가 없어진 것은 아니다.
