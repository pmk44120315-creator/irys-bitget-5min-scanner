# IRYS V37 조기 진입 기회 감시 — 구현/검증 설계

작성 2026-11-06. 사용자 승인: "그럼 시작해". 기존 V35.1 운영본/급락 V34/별도 ChatGPT 감시기 동작 중단·변경 없이 진행.

## 판단 문제
구조적 지연은 알림 전달 시간뿐 아니라 종목 선택 단계부터 발생한다. 현재 비트겟 V30 후보선정은 이미 이전 3~9분 대비 변화폭이 큰 종목을 순위화하고, 빗썸 V28 후보선정은 이미 방향 움직임이 누적된 시장 강도에 의존한다. CYBERUSDT 롱은 11:51 발송 후 5분 -2.49%. 2026-11-06 16:38 이후 V36 연구 후보 측정 방향 성적은 만족스럽지 않으며 실전과 동일집단 매칭이 안 된 상태. 기존 V33 초기 후보 연구는 빨리 잡았다는 이유만으로 더 정확해지지 않음을 확인함.

## 대안 비교
- A. V30 방향 게이트 삭제/완화: 더 빠른 신호는 가능하나 반례에 의해 무근거 매매 알림 폭증 위험. 채택 안 함.
- B. V30의 매수·매도 체결 인식의 확인 창만 단축: 지연 감소는 일부지만 그 이전부터 이미 큰 폭 움직인 종목이 우선 선택되는 원인은 못 고침. 선행 탐색과 병행할 후속 실험으로 남김.
- C. 전시장 가격·거래대금 이력의 **선행 변화**를 먼저 추적하고, 이후 공식 분봉 경로·늦음 지표로 실증: 채택. 실전 진입 허가는 금지한 독립 운영 실험으로 시작.

## 설계
1. Bithumb의 기존 V30 state에 보존된 `v28.assets[symbol].points` (시각/원화가격/일간 누적 거래대금)를 **당시 알려진 시각만** 사용한다. 4개 관측점은 지표 기준선의 최소 수치 검증이며 '20개 연속 상승' 같은 추세 요구가 아니다. 절대거래대금 하한은 추가하지 않는다.
2. Bitget은 공식 ticker 전체와 기존 V24의 암호화폐 신원 검증 종목 집합을 결합한다. Bitget 24시간 롤링 거래대금 차이는 정확한 5분 수급/CVD가 아니므로 `ROLLING_24H_...PROXY`로 저장한다. 가격정보만 있는 경우 진입 방향을 확정하지 않는다.
3. 이전 거래대금 변화의 중앙값 대비 최근 가속도를 관찰하되, 누적 수치 리셋·출처가 다른 타임스탬프·유통량 부재는 오류 또는 `INSUFFICIENT_FLOW`로 분리한다. 이미 진행된 누적 방향 변화가 과거 가격 변동의 확장배수를 넘으면 `EXTENDED_MOVE`로 명시한다. 이는 연구용 탐색/구분이지 검증된 거래 규칙이 아니다.
4. `EARLY_FLOW_LEAD` 관측은 `trade_permit:false`, `entry_ready:false`, 확률:null로 고정한다. 독립 30분 종목·방향 에피소드 식별자를 사용하고, 5/15/30/60분 공식 분봉 결과를 사후에만 접합한다. 실전 Telegram ACK나 실주문 성적과 섞지 않는다.
5. 모든 결과는 `data/v37_early_latest.json`·`data/v37_early_state.json`에만 저장한다. 기존 데이터·Worker·Telegram 메시지·Secret·Cron은 건드리지 않는다. source heartbeat와 누락·실패를 구분하고, 실제 배포 검증은 GitHub Actions 정규 producer 완료 후 자연 실행으로 확인한다.

## 독립 평가와 승격 금지
같은 종목·같은 시간·동일한 비교가능 진입호가, 수수료/슬리피지/대기시간, 미래데이터 미사용 조건으로 V35.1 실제 발송 vs V37 당시 관측을 비교해야 한다. 미측정은 성공으로 처리하지 않는다. 이른 포착 시간과 기회 유지율 및 역행폭을 주 지표로 보며, **후행 신호가 줄었다는 사실만으로 수익률/정확도 향상을 주장하지 않는다.** 실전 방향 모델 교체에는 별도 근거·회귀테스트·되돌리기 절차가 필수.
